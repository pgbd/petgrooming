## Panel access (deny by default)

Filament lets any authenticated user into the panel in the local environment, and refuses everyone elsewhere unless the `User` model says otherwise. An automated review flagged that login alone was the only check.

Now `User` implements Filament's panel-access contract and defers to the `access-admin-panel` gate, which denies everyone. A user the gate refuses cannot sign in and gets 403 on `/admin`. M1 (IDN-3) replaces the gate body with a role check. Tests cover the default deny, a refused sign-in, a 403, and a user the gate explicitly allows.

Because the gate denies everyone, no real staff account can enter the panel on the VPS until M1 defines roles. A real staff login over HTTP on the VPS therefore needs the M1 role check first. The VPS result above used the same gate override as the local tests.
